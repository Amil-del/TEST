1) Блочная корзина
Общая временная сложность нашего решения имеет вид: O(n + k), где n - это количество элементов в исходном массиве и k — это количество корзин (количество интервалов, определяемых минимумом и максимумом значений). Чтобы создать необходимое количество корзин, мы сначала находим минимальный и максимальный элемент в массиве. Этот процесс требует линейного прохода по всему списку, следовательно, временной расход здесь составляет O(n). Затем каждый элемент распределяется по соответствующей корзине. Для каждого элемента выполняется операция деления и добавления в соответствующий список. Поскольку каждому элементу сопоставляется одна корзина, этот этап также занимает O(n) операции. Для каждой корзины выполняется внутренняя сортировка её содержимого. Финальный этап объединяет отсортированные корзины в одну результирующую структуру. Итого, временная сложность нашей реализации составляет O(n). Тем не менее, важно учитывать влияние количества корзин (k), которое добавляется к общей оценке. Таким образом, правильнее говорить о временной сложности как O(n + k), где k — это количество используемых корзин.
2) Блинная сортировка
Функция flip, используемая для переворота начала массива, выполняется за линейное время относительно размера переворачиваемой части массива, поскольку нам нужно поменять местами элементы. Время переворота составляет O(k), где k - длина переворачиваемого фрагмента. Функция find_max_index проходит по первым n элементам массива и выбирает наибольшее число. Эта операция также занимает линейное время O(n). Цикл продолжает выполняться, пока не останутся лишь две позиции (curr_size > 1). При каждом проходе цикла выполняются операции поиска максимального элемента и два переворота (если максимум не находится на своём месте): поиск максимума и флипы. Временная сложность алгоритма блинной сортировки в худшем случае квадратична относительно длины входного массива. Алгоритм подходит для небольших размеров входных данных, однако становится неэффективным при увеличении количества элементов.
3) Сортировка бусинами
Здесь создаётся двумерный массив размера len(lst) x max_value, где len(lst) — длина исходного списка, max_value — наибольшее число в списке. Время заполнения матрицы пропорционально произведению размеров массива, следовательно, временная сложность равна O(N * M), где N — размер исходного списка, а M — максимальная величина элемента в списке. Мы обрабатываем каждый столбец отдельно, и эта операция выполняется для каждого столбца, всего M столбцов (M равно максимальному элементу). Операция прохода по столбцам занимает O(M), а сумма операций внутри столбца составляет O(N). Следовательно, общая временная сложность второго этапа также равна O(N * M). Таким образом, временные затраты состоят из трёх частей: построение матрицы: O(N * M), гравитация: O(N * M), преобразование результата: O(N * M). Следовательно, итоговая временная сложность равна O(N * M). Это связано с тем, что каждый этап работает линейно относительно произведения размера входного списка (N) и максимального значения (M). Чем больше максимальный элемент и длиннее список, тем дольше будет выполняться алгоритм.
4) Поиск скачками
Временная сложность алгоритма Jump Search оценивается как O(√N). Алгоритм разделяет исходный отсортированный массив на блоки размером примерно корень из N, где N - длина массива. Сначала производится перебор блоков ("скачки") длиной около корень из N до тех пор, пока не найдётся блок, в котором находится искомый элемент. После нахождения подходящего блока осуществляется простой последовательный поиск внутри блока, занимающего также порядка корень из N. Тем не менее, Jump Search часто применяется там, где структура данных допускает быстрое перемещение по определённым промежуткам, но при этом бинарный поиск либо неудобен, либо невозможен ввиду особенностей организации данных.
